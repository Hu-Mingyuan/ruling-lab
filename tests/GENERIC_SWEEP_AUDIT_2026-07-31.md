# Generic-sweep audit of the ruling atlas

The static front end does not count rulings.  It displays certificates
generated by `downloads/direct-ruling-counter`.

## Defect

The counter uses the x-sweep `tau=(1,0)`.  Its arrangement builder rejects
triple intersections at one point, but it does not reject distinct crossings
having the same x-coordinate.  The type-B audit nevertheless probes the
unperturbed diagram on `tau(p) +/- 1/10`.  Hence a probe may cross a whole
simultaneous block instead of one crossing.

Among the 61 atlas diagrams (1190 crossings), 12 diagrams have this defect,
with 17 tied critical levels:

## Exact recount

Each affected diagram was recounted with the same geodesics and basepoint but
with a primitive integral covector `tau=(M,1)` in the same transverse chamber,
chosen so all crossing times in `S1` are distinct.  We used the unimodular
companion `sigma=(-1,0)` and reran the complete no-cutoff disk/annular solver.

Every total ruling count is unchanged.  Eleven diagrams also retain exactly
the same disk and annular mask/multiplicity sets.  One diagram changes:

```text
polygon-c848bca89e, vertices [(0,2),(2,0),(4,1),(2,2)]

genus 0: (disk,annular,total) (10,8,18) -> (7,11,18)
genus 1: (disk,annular,total) (7,1,8)   -> (6,2,8)
genus 2: (disk,annular,total) (1,0,1)   -> (1,0,1)
```

The changed raw certificates are:

```text
g=0 old-only disk: 5429c, a154a, df089, f6885
g=0 new-only disk: a154c
g=0 old-only annular: 11542
g=0 new-only annular: 11544, 5429a, df083, f6883

g=1 old-only disk: b355b, f6e9d
g=1 new-only disk: b355d
g=1 new-only annular: f6e9b
```

Thus the atlas grand total of 1601 is unchanged.  The source-and-download fix
does not rewrite the static SVG gallery: by design those precomputed images
remain the legacy x-sweep representatives.  Regenerating the two affected
disk/annular sectors is only needed if the gallery itself is later required
to display generic-sweep certificate labels.
